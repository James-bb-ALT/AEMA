# AEMA 2.0.1 — validação de seleção LLM

Correção incremental na leitura local: o modelo retorna somente IDs de evidência. A
aplicação valida evidências positivas e mapeia cada uma a uma ação revisada determinística,
eliminando sugestões de texto incompatíveis produzidas pelo modelo. A inferência segue
offline, com Qwen3 e o pipeline Android existente.

Inclui testes sintéticos de oito classes, repetidos três vezes com modelo Qwen3 real no
emulador; cenário integrado de parsing/exportação/importação; simulação cronológica de
previsão e ensaio local de recursos LoRA. O caderno
[Simulação e viabilidade](../estudos/05-SIMULACAO-E-VIABILIDADE-LLM.md) descreve método,
resultados e limites. Dados e métricas brutos permanecem em artefatos locais ignorados
pelo Git. Nenhuma precisão real de bateria ou treinamento pessoal é alegada.

Versões: Android `2.0.1` (código `20001`), pacote Python `2.0.1`, documentação `2.0.1`.
Nenhum contrato de dados ou dependência do produto mudou.

Verificação: 202 testes Python passaram (cobertura 92,74% na execução com coverage);
Ruff passou. Android instrumentado: 8 no total, 7 passaram, 1 teste condicional de
alarme foi ignorado e zero falharam. A matriz de LLM executou 24 inferências reais em 328,4 s.
`assembleRelease` e `lintVitalRelease` passaram para ambos APKs. Ambos foram conferidos
com `apksigner` e AAPT: versão 2.0.1/código 20001, sem permissão INTERNET. O APK com
modelo contém os 639.446.688 bytes esperados, com SHA-256 conferido contra o modelo
oficial Qwen3 Q8_0. Os cinco artefatos de distribuição incluem checksums SHA-256.

A versão da aplicação exibida nos resultados instrumentados é 2.0.0 porque essa rodada
foi iniciada antes da atualização final dos metadados. O APK e os manifests 2.0.1 foram
gerados e validados depois; o código funcional testado é o mesmo. A diferença foi
somente a versão nominal/código, sem mudança de lógica após os testes.
